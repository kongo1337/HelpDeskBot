# helpdesk-bot

Бот-помощник службы технической поддержки с веб-страницей чата. Работает полностью локально: языковая модель запущена через [Ollama](https://ollama.com) на домашнем ПК, наружу ничего не отправляется.

Бот ведёт себя как сотрудник поддержки: сначала задаёт 1–2 уточняющих вопроса, потом даёт решение по шагам, а если решить не получается — пересказывает проблему для передачи инженеру.

Учебный проект: путь из хелпдеска в DevOps и MLOps. Каждый этап добавляет одну технологию.

## Возможности

- Веб-страница чата, ответ печатается по мере генерации (стриминг)
- Память разговора: модель видит всю переписку
- Разговоры хранятся в SQLite и переживают перезапуск сервера
- Поведение бота задаётся системным промптом в `prompts/system.md`
- Понятные ошибки, если Ollama не запущена или не отвечает
- Запуск как systemd-сервис с автозапуском и автоперезапуском при падении
- Консольная версия `bot.py` со статистикой скорости модели

## Стек

Python 3.10+, FastAPI, Uvicorn, SQLite, Ollama (модель `qwen3.5:9b`), HTML + JavaScript без фреймворков, systemd.

## Установка

Нужны Linux, Python 3.10 или новее и установленная Ollama с моделью:

```bash
ollama pull qwen3.5:9b
```

Клонировать репозиторий и поставить зависимости в виртуальное окружение:

```bash
git clone <адрес репозитория> ~/projects/helpdesk-bot
cd ~/projects/helpdesk-bot
python3 -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt
```

## Запуск

### Для разработки

Из корня проекта, где лежит `app.py`:

```bash
source .venv/bin/activate
uvicorn app:app --reload
```

Страница чата: http://127.0.0.1:8000/
Документация API: http://127.0.0.1:8000/docs

Сервер слушает только `127.0.0.1`. Чтобы открыть страницу с другого компьютера, пробросить порт через SSH:

```bash
ssh -L 8000:localhost:8000 kongo
```

### Как сервис

```bash
sudo cp deploy/helpdesk-bot.service /etc/systemd/system/
sudo systemctl daemon-reload
sudo systemctl enable --now helpdesk-bot
```

В unit-файле прописаны имя пользователя и путь к проекту — поправить под себя перед копированием. Перед запуском сервиса остановить `uvicorn --reload`, иначе порт 8000 будет занят.

Управление:

```bash
systemctl status helpdesk-bot          # состояние
sudo systemctl restart helpdesk-bot    # после изменения кода или промпта
journalctl -u helpdesk-bot -f          # логи в реальном времени
```

### Консольная версия

```bash
python bot.py
```

## API

| Метод | Путь | Что делает |
|---|---|---|
| `GET` | `/` | страница чата |
| `GET` | `/health` | проверка, что приложение живо |
| `POST` | `/chat` | вопрос → ответ целиком одним JSON |
| `POST` | `/chat/stream` | вопрос → ответ по кусочкам (NDJSON) |
| `GET` | `/sessions/{session_id}` | история разговора |

Тело запроса для `/chat` и `/chat/stream`:

```json
{"message": "Не печатает принтер", "session_id": "необязательно"}
```

Без `session_id` начинается новый разговор, сервер возвращает его номер. Неизвестный `session_id` тоже начинает новый разговор.

Пример:

```bash
curl -X POST http://127.0.0.1:8000/chat \
  -H "Content-Type: application/json" \
  -d '{"message": "Не печатает принтер"}'
```

Поток событий `/chat/stream` (`-N` отключает буферизацию curl):

```bash
curl -N -X POST http://127.0.0.1:8000/chat/stream \
  -H "Content-Type: application/json" \
  -d '{"message": "Не работает интернет"}'
```

Типы событий: `session` (номер разговора), `token` (кусочек текста), `done` (ответ сохранён), `error`.

Коды ошибок: `503` — Ollama не запущена, `504` — модель не ответила вовремя, `502` — Ollama вернула ошибку, `422` — неправильное тело запроса.

## Как это устроено

**Память.** Модель сама ничего не помнит. Приложение хранит переписку и при каждом вопросе отправляет в Ollama весь список сообщений: системный промпт, историю разговора и новый вопрос.

**Хранение.** Две таблицы SQLite: `sessions` (разговоры) и `messages` (сообщения с ролью и временем). Вопрос и ответ записываются вместе одной транзакцией и только после того, как ответ пришёл полностью. Если Ollama упала или связь оборвалась посреди ответа, в базе не остаётся половины разговора.

**Стриминг.** Ollama → `app.py` → браузер, на каждом звене поток по строкам. Приложение подключается к Ollama до начала ответа клиенту, поэтому ошибка подключения приходит обычным кодом 503.

**Системный промпт** лежит в `prompts/system.md` и читается при старте. Поведение бота меняется правкой этого файла, а история изменений видна в Git: `git log -p prompts/system.md`.

## Что я узнал

### Этап 2: Ollama + Python-скрипт

- HTTP API Ollama: `/api/chat`, роли `system`, `user`, `assistant`, параметр `stream`
- Python: `requests`, словари и списки, `while`/`break`/`continue`, f-строки, `try/except` с конкретными типами ошибок
- Память диалога — это просто список сообщений, который программа каждый раз пересылает целиком
- Системный промпт — главный рычаг управления поведением модели без изменения кода
- Метрики Ollama: `eval_count`, `eval_duration` в наносекундах, скорость в токенах в секунду
- venv, `requirements.txt`, Git

### Этап 3: FastAPI + страница чата

- FastAPI: эндпоинты через декораторы, проверка запросов через Pydantic, страница `/docs` строится сама
- Коды HTTP 502/503/504 — ошибка не у меня, а у сервиса, в который я хожу
- Сессии: каждый разговор получает свой uuid, его создаёт только сервер
- SQLite: таблицы, внешний ключ, транзакции через `with`, параметры `?` вместо f-строк — защита от SQL-инъекций
- Стриминг: генераторы с `yield`, `StreamingResponse`, формат NDJSON, чтение потока в браузере через буфер
- JavaScript: `fetch`, `async`/`await`, `localStorage`, `textContent` вместо `innerHTML` — защита от XSS
- systemd: unit-файл, запуск не от root, автозапуск, автоперезапуск, логи через `journalctl`

Что неудобно без контейнеров: пути и пользователь прописаны под конкретный компьютер, Python и библиотеки стоят прямо в системе, unit-файл копируется вручную, Ollama и бот настраиваются отдельно. Это решает Docker на следующем этапе.

## Грабли

| Что случилось | Причина | Решение |
|---|---|---|
| `curl: (35) TLS connect error ... wrong version number` | Запрос по `https://` к Ollama, которая отвечает по HTTP | Адрес `http://localhost:11434` |
| Бот не помнит имя из первого сообщения | В запрос уходил только текущий вопрос, а не вся история | Передавать весь список: `"messages": messages`. Для отладки — `print` перед запросом |
| `Could not import module "app"` | `uvicorn` запущен из папки `static`, а не из корня проекта | Запускать из папки, где лежит `app.py`. В systemd — `WorkingDirectory` |
| После изменения страницы стриминг не работает | Браузер показывал старую версию страницы из кэша | Обновить без кэша: `Ctrl+Shift+R` |
